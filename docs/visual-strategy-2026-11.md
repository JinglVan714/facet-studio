# 视觉策略：关键帧收紧，优先语义绘图（2026-11）

> 状态：2026-11-08 用户确认方向。内容质量（尤其插图）是下一阶段主线程；本文件定义“什么视觉载体该用、关键帧什么时候能用、图注怎么处理”。
> 上位：[writing-v5-architecture.md](writing-v5-architecture.md) / [writing-rebuild-brief.md](writing-rebuild-brief.md) §2/§3；实现落在 `skills/writing/*`、`content_manuscript`、`svg_pass`。
> 原则：**视频关键帧是原始画面的截取；文章插图是对语义信息的提炼、重组和可视化。两者设计目标不同。** 默认用语义绘图/原生内容组件；关键帧是最后手段，必须非常紧。
>
> **2026-11-10 修订（当前）**：SVG 只保留 `flow`（步骤）、`tree`（层级/思维导图）、`timeline`（时间线）三类；`stack` / `two-axis` / `compare` / `matrix` / `cards` / `cause` 已从 `svg_pass` 与 active skill 删除。统计/对比/分布/因果/观点用 Markdown 表格或正文；每篇 0–2 张；未知 kind 直接跳过，不兜底成 flow。

## 1. 为什么不能直接拿关键帧当插图

| 问题类型 | 具体表现 |
|---|---|
| 信息承载不足 | 单帧只记录某个瞬间，无法完整表达复杂知识、多个要点或逻辑关系。 |
| 概括性不足 | 画面局限于视频当时的场景，难以提炼整段内容的核心观点和知识结构。 |
| 博主肖像权风险 | 可能包含博主、嘉宾或其他人物肖像，直接截取和传播可能涉及肖像权及隐私问题。 |
| 画面美观度不足 | 表情不自然、动作定格、构图随意、光线不佳、画面模糊等问题。 |
| 理解成本较高 | 视频画面往往缺少必要的文字标注、信息层级和视觉引导。 |
| 上下文依赖性强 | 截帧可能依赖前后视频内容才能理解，脱离原视频后容易产生歧义。 |
| 信息冗余 | 可能包含无关背景、人物、道具、字幕、水印等视觉噪声，真正有价值的信息占比低。 |
| 表达形式受限 | 难以直观呈现抽象概念、因果关系、流程、数据对比、层级结构等非具象信息。 |
| 与正文匹配度低 | 画面可能只是视频中的一个场景，与文章当前段落的核心信息并不完全对应。 |
| 版权与素材风险 | 画面可能包含第三方图片、影视片段、品牌素材或其他受版权保护的内容。 |
| 视觉风格不统一 | 不同视频的画质、色彩、构图和拍摄风格差异大，文章整体视觉体验不一致。 |
| 排版适配性差 | 视频截图的宽高比、字幕位置和主体构图不一定适合文章版式，容易裁切/留白。 |

核心痛点（6 类）：

1. **信息密度不足**：单帧无法有效呈现复杂内容。
2. **语义概括能力不足**：无法主动提炼和重组核心知识与观点。
3. **版权与肖像风险**：人物肖像、隐私、第三方素材版权。
4. **视觉质量不可控**：模糊、不美观、构图不合理、风格不统一。
5. **信息理解效率低**：缺结构化标注，视觉噪声多，脱离视频上下文难理解。
6. **内容表达能力受限**：难以表达抽象概念、逻辑关系、流程、数据和知识结构。

## 2. 产品决策

### 2.1 载体优先级（从高到低）

1. **原生内容组件**：Markdown Table、Code Block、Ordered List、Checklist、LaTeX、Callout/Highlight Card。
2. **语义绘图**：SVG 仅限步骤图（`flow`）、层级/思维导图（`tree`）、时间线（`timeline`）；统计/对比/分布/因果/观点用 Markdown 表格或正文。
3. **关键帧**：只有通过下面“极紧门槛”时才用；默认 0 张。
4. **没有合适的视觉**：文字说清楚，不硬编画面。

> 原则：根据内容选择表达载体，而不是强制所有内容都生成 SVG。代码/命令用 Code Block；多维数据用 Table；数学用 LaTeX；长步骤用 Ordered List；简单注意事项用 Checklist；只有步骤/层级/时间线用 SVG/Mermaid；统计、对比、因果、观点用 Table/正文/Callout。

### 2.1.1 关系测试与盖图测试（画之前先过）

**关系测试**：写图之前，先用一句话填完：

> 这张图要让读者看见【A】和【B】之间的【关系】。

关系词必须是：对照/边界、组成/层级、先后/循环、因果、权限有无、选择分支、分布/阈值、换算/归一。

填不出两个实体和一个关系词，或只能写出“A、B、C 三类”，**不要画**；用文字或表格。

**盖图测试**：

- 盖住图，正文是否仍然完整？是 → 图可能只是装饰。
- 盖住正文，图是否还能说出一个关系？否 → 图是名词卡。
- 图的结论是否在图上（箭头/轴/分组/阈值线/槽位/标注），而不是只在图注/caption 里？
- 图的框是否和 H2 一一对应？是 → 这是目录，不是关系，删。

**0 图是正常结果。** 不要用“视觉缺口”逼自己填图；只有“这个关系没有图就说不清”才补。

**关系类型 → 载体**：

| 正文关系 | 首选载体 | 不该用的信号 |
|---|---|---|
| 名词/术语解释 | 一句话；概念卡少用 | 术语只是顺带提到；卡片只是复述定义；多张概念卡替代正文 |
| 职责区分 | 2 列对照表或分层图 | 两方没有共同维度；只是并列名词；没有“边界/交接” |
| 模块组成 | 树/架构图（父子关系真实） | 分组是人为的；类别互相重叠；根节点是容器不是组件 |
| 执行过程 | 流程图/循环图（有顺序、判断、回路） | 只是 H2 目录；并行输入被串成一条线；没有判断/回路 |
| 权限差异 | 矩阵/对照表（行=能力，列=角色/配置） | 只有一方配置；单元格没有内容稿依据 |
| 模式选择 | 决策树/场景对比（有判别条件） | 内容说“看仓库”；没有每模式的具体差异；判别条件是编的 |
| 因果 | 因果链（A→B→C，带机制） | 只是时间顺序；箭头不表示因果 |
| 数据分布/阈值 | 图表/数轴（看形状、缺口、排序） | 只需精确查值；用表格就够了 |

### 2.2 关键帧极紧门槛（全部满足才可用）

- **不可替代**：这张画面承载了文字/表格/SVG 说不清的**关键证据**（真实结果、关键状态、操作现场、前后对比），不是气氛图、封面图、装饰图。
- **自解释**：脱离视频上下文，读者只看这张图 + 正文也能明白它在证明什么。
- **视觉合格**：清晰、构图可读、光线/色彩可接受；没有表情定格、动作糊、主体被裁。
- **无风险元素**：无博主/嘉宾可识别肖像（或已获得授权）、无隐私信息、无第三方影视/品牌素材、无水印/平台 UI/烧录字幕等噪声。
- **与段落严格对应**：画面就是当前段落的核心信息，不是“视频里出现过”。
- **没有更好的载体**：能用表格/SVG/代码/清单表达时，不用关键帧。
- **权利清楚**：素材有使用权；不确定就不用。

数量：

- `long_article`：默认 0；最多 **1** 张关键帧。
- `wechat_article`：默认 0；最多 **1** 张。
- `xiaohongshu_note`：封面可以用 1 张通过门槛的关键帧；没有就文字封面/文字卡；正文卡最多再 1 张。
- 任何形态：**宁缺毋滥**；没有通过门槛的关键帧就 0 张，不拿“看起来还行”的帧凑数。

### 2.2.1 关键帧的定位：真实场景还原（Scene Illustration）

关键帧不是默认配图，也不是完全禁用；它是一种**特殊插图类型**：真实场景还原。SVG 负责知识结构和抽象信息，关键帧负责真实对象/动作/场景/视觉证据。

适用（满足之一，且通过 §2.2 门槛）：

| 场景 | 表现 | 示例 |
|---|---|---|
| 展示真实操作 | 动作/操作过程 | 做菜、设备操作、软件操作 |
| 展示具体对象 | 物体本身是讲解对象 | 产品外观、设备、食材、建筑 |
| 展示真实场景 | 环境提供文字替代不了的背景 | 旅行地点、实验现场、活动现场 |
| 展示前后变化 | 变化/结果 | 改造前后、实验结果、制作成品 |
| 展示具体细节 | 需要观察局部特征 | 产品细节、操作手法、材质纹理 |
| 展示视觉证据 | 画面本身是观点/结论的证据 | 实验现象、实际测试、现场演示 |

不适用（优先用替代载体）：

| 场景 | 原因 | 替代 |
|---|---|---|
| 抽象概念解释 | 真实画面难表达抽象语义 | 概念示意图 |
| 多个知识点归纳 | 单帧承载不了多个信息单元 | 思维导图/层级图 |
| 复杂流程讲解 | 单帧缺流程和顺序 | 流程图/时间线 |
| 观点和方案比较 | 缺结构化对比 | 对比图/矩阵 |
| 因果关系分析 | 画面难表达逻辑关系 | 因果图 |
| 数据和统计分析 | 普通画面无法准确表达量化信息 | 数据图表/表格 |
| 核心观点总结 | 场景画面不一定能概括观点 | 观点卡 |
| 博主个人叙述 | 肖像风险，画面未必有信息价值 | 抽象示意图/文字 |

质量条件（必须：语义相关、信息价值、可理解、画面质量、肖像/版权合规；加分：概括性、视觉美观度）。

关键帧**不需要很强概括性**：视频讲一个具体操作，一张清晰展示工具和手法的画面就有插图价值；它不必概括整段教程。

### 2.2.2 插图决策流程

```text
正文这段有视觉化需求吗？
  否 → 纯正文
  是 → 先判断关系类型：职责/模块/流程/权限/选择/因果/数据/名词
        → 按“关系类型 → 载体”先选表格/代码/列表/SVG/观点卡
        → 只有“需要展示真实对象/动作/场景/证据”才评估关键帧
             关键帧：语义相关、信息明确、画面清晰、使用合规？
               满足 → 关键帧
               不满足 → 放弃，回到 SVG/表格/代码/纯正文
```

三种策略互相补充：

1. **真实还原型**：关键帧，强调真实性（物体、场景、操作、证据）。
2. **知识解释型**：SVG，强调概括性（概念、关系、流程、逻辑）。
3. **信息组织型**：表格/代码块/列表，强调检索和阅读效率。

### 2.3 图注：默认不加

- 文章图片默认写 `![](figures/fig-01.jpg)`，**不加 figcaption**；图本身或正文句子承担说明。
- 需要“看哪里/这说明什么”时，写成正文里的一句话，或图内标注；不写图片下方的 caption。
- 不把内容稿里的 `画面参考` 描述原样复制成图注；那是选图元数据，不是正文。
- SVG 图把标题/标签/图例画在图内；不另加 caption；图内标注“示意”。
- 可访问性 alt 可留空或极短；不为了 alt 写一段解释。

### 2.4 SVG 信息图类型

按语义结构选择，不按“好看”选择：

| 类别 | 图形 | 适用 |
|---|---|---|
| 结构与关系 | 思维导图、概念关系图、层级图、分类图、维恩图 | 知识梳理、概念关联、分类 |
| 流程与步骤 | 步骤图、流程图、循环图、时间线、漏斗、决策树 | 教程、方法论、事件发展 |
| 清单与组成 | 配料表、材料/工具清单、检查清单、组成结构图 | 美食、DIY、产品介绍 |
| 比较与决策 | 优缺点对比、A/B、多维矩阵、四象限 | 测评、方案选择、观点辨析 |
| 因果与逻辑 | 因果链、鱼骨图、反馈回路、论证结构 | 原理分析、原因解释 |
| 数据与统计 | 柱状/条形/饼/环/趋势/指标卡 | 数据、比例、趋势 |
| 空间与实体 | 结构标注、剖面、布局、原理示意、部件分解 | 产品结构、设备、技术原理 |
| 概念与隐喻 | 概念图标、象征图、隐喻图、抽象示意 | 抽象观点、复杂知识 |
| 观点与摘要 | 核心观点卡、引用卡、三点总结、问题/方案卡 | 总结、观点提炼 |
| 代码与技术 | 代码片段卡、架构图、时序图、数据结构图、API 交互 | 编程、AI 科普 |

实现范围（v1）：

- 当前 `svg_pass` 只支持 `flow`（步骤）、`tree`（层级/思维导图）、`timeline`（时间线）；`stack` / `two-axis` / `compare` / `matrix` / `cards` / `cause` 已删除。
- 数据图表：**精确查值/多字段对照 → Markdown Table；看分布形状、阈值缺口、排序变化 → 图表（SVG/原生 Chart）**。不要用表格代替分布，也不要用图代替查值表。柱状/趋势图后续再扩展 `bars/line`，本轮不硬做。
- 空间/实体、概念/隐喻不强行生成；没有可靠映射就退回文字/表格/简单示意。

### 2.5 视觉计划（写作前，不输出给读者）

每个节拍先写一行视觉计划：

> 关系类型 → 载体 → 放哪 → 为什么不是纯文字/表格；没有关系就写“纯文字”。

规则：

1. **先过关系测试**（§2.1.1）；填不出两个实体和一个关系词，不画。
2. 按“关系类型 → 载体”选 Table / Code / List / Checklist / LaTeX / SVG（kind）/ 关键帧；关键帧最后。
3. **0 图是正常结果**；不要用“视觉缺口”逼自己填图。
4. 同一关系只用一个载体；不同关系可以各自配图；相邻两节不要重复同一关系。
5. 图放在**关系句之后、推论句之前**；不要在术语落地前放一张含未解释术语的图。
6. 图应画**文章的控制性 idea**，不是内容稿/视频的时间顺序。
7. 如果图只是 H2 目录，删。
8. 如果一节只有一句关系断言、没有例子/数字/图，合并到上一节或补一个具体实例。

数量：**不设固定上限；按关系/结构复杂度决定；0 正常。** 长内容/复杂关系可以多张；用户可要求多图或少图，服从 request。不是“越多越好”，也不是“越少越好”。

表格规则：**≥2 个对象 × ≥2 个字段，且读者需要横向对照时用表格**；单对象清单用列表。不要用“字段重复三次以上”的旧规则。

表格 vs 图表：**精确查值/多字段对照 → 表格；看分布形状、阈值缺口、排序变化 → 图表。** 同一关系不要同时用表格和图；如果同时用，必须一个查值、一个看形状，并在正文说明分工。

SVG 占位符写成关系，不写几何：

`<!-- svg: 关系类型 | A | B | 关系/方向 | 读者要看到的结论 -->`

例：`<!-- svg: 对照 | 方案 A | 方案 B | 同一维度上的两个差异；读者要看到的结论 -->`

图的数量按关系复杂度决定，不设固定上限；关键帧路径只从内容稿复制；不放不存在的路径；不描述没看到的画面；图注默认省略。

**反模式（出现就删/换）：**

- **载体兜底**：用 `compare`/`cards`/`two-axis` 硬画它们画不出的关系；现有 kind 不匹配时，改用表格/文字。
- **名词卡**：一个框一个名词，框里是定义，箭头只表示“然后”。
- **目录流程**：四个阶段框和 H2 一一对应，删掉图正文不缺。
- **空区域对照**：左“A 区域”右“B 区域”，没有共同轴、距离、差异。
- **假树**：根是系统名，子节点是功能列表；分组是后加的，父子关系不真实。
- **假矩阵**：单元格没有内容稿依据，靠常识填。
- **重复图**：同一关系既有表格又有图。
- **过早图**：图里出现下一段才解释的术语。
- **万能图**：任何文章都能套的“输入→处理→输出”。

写完自审：

- 盖住图，正文是否仍然完整？盖住正文，图是否还能说出一个关系？
- 图的结论是否在图上，而不是只在 caption 里？
- 框是否和 H2 一一对应？是 → 目录，删。
- 有没有为了凑图放的关键帧/概念卡？删。
- 每张图是否回答了一个读者问题？不能就删。
- 有没有给图加了不必要的 caption？删。
- 表格/代码/清单是否比图更合适？换。

- `src/facet_studio/writing_v4/visual_audit.py`：writing layer 的视觉审计；用 `deepseek-flash` 的视觉输入判断候选帧，只把通过帧留在 run content；`plan_article` 调用。

### 4.1 关键帧视觉审计（writing layer，不是证据层）

- 官方依据：DeepSeek Vision guide（`deepseek-flash` 支持 image input；OpenAI-compatible content blocks；单图上限 1024 tokens）。

## 5. 验收

- ≥2 视频 / ≥2 形态重跑同一 request；不是单篇调参。
- 每篇关键帧 0–1 张；每张通过 §2.2 清单。
- 图注默认 0 条；需要说明时在正文/图内。
- SVG/表格/代码/清单按语义选择；不为了图而图。
- 用户人工验收是唯一发布门；测试绿/跑通不算内容质量通过。

## 6. 不做

- 不把关键帧当默认配图；不为了“视觉丰富”硬塞。
- 不用生成图冒充视频证据；生成图只作 editorial，且需标注。
- 不按单篇调图/调 caption；不在 renderer 里掩盖内容问题。
- 不加 editor/checker 多轮改稿；一次 writer + 自审。
