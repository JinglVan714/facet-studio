## q9 synthesis — PTC 的适用与反噬

**Key points**

1. PTC 保留标准模式能力，但把“模型逐个调用工具”改成“模型写脚本、Agent 框架执行脚本”；实测请求里只暴露 `runcode`。
2. 适合工具链长、需要把 B→C→D 串起来的自动化任务：减少模型调用次数、让中间细节不占上下文、省 token。
3. 反噬条件：AI 写的脚本可能出错或执行失败，要打回反复修改，反而增加调用；这是视频明确说的“理想情况”之外。
4. 结论应是条件性的：不是“PTC 总是更快/更省”，而是“在能稳定生成正确脚本的长工具链上更省；脚本不可靠时可能更贵”。

**Evidence**：seg6-p02 269.1–307.6s；seg6-p03 307.9–332.7s；seg7-p02 403.6–423.9s；seg7-p03 424.2–448.6s。

**Scoring**

- 2：定义/工具列表 + 适用条件 + 反噬条件，结论有条件性。
- 1：覆盖其中两项；或只给“PTC 更快”的结论但提到 caveat。
- 0：说 PTC 总是更省；把 PTC 说成去掉模型/不需要脚本；编造量化节省。
