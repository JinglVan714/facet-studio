# Visual reference：图/表/帧优先

> 视觉是文章的一部分，不是装饰；能用图/表说清的结构，不写成一大段文字。
> 真实帧是视频证据；派生图表/示意图/表格是 editorial（由证据派生）；生成图只作 editorial。

## 1. 什么时候用什么

| 内容 | 首选 | 说明 |
|---|---|---|
| 流程/步骤/管道 | diagram | 节点/边按证据顺序；不补视频没说的边 |
| 机制/因果/架构 | diagram | 只画能回指 claim/evidence 的关系 |
| 对比/分类/模式 | table | 维度明确，行列来自证据 |
| 数字/趋势/分布 | chart | 数据点必须来自 evidence；不编造 |
| 真实 UI/演示/操作 | real_frame | 只在画面确实展示该操作/结果且可读时用 |
| 概念/隐喻/氛围 | generated_image 或 image_prompt | 只作 editorial；不承担证据功能 |
| 没有合适图 | text/no_visual | 在 self-review 里说明为什么 |

## 2. 真实帧规则

- 只在真实帧展示操作/结果/claim 且可读时用；关键帧不一定好，不要硬插。
- 优先完整、可读的状态；渐进展示取最终展开态。
- caption 只写“看哪里”，不写正文摘要；时间码/来源进 audit。
- 空 caption/截断 caption 要记录；不把 VLM/OCR 的整屏文字当画面事实。
- 真实帧是证据；裁剪图仍指原帧时间。
- 如果正文说“视频给了一张图”，文章里应该真的放那张图；如果放的是示意图，正文要改口，或在 caption 说明“这是示意，不是原图”。

## 3. 图表/示意图/表格规则

- chart：每个数据点带 source evidence/claim；没有数字不画；近似/舍入要标注。
- diagram：每个 node/edge 带 source claim/evidence；不补视频没说的关系；不装饰。
- table：行列来自证据；不编单元格；比较维度要明确。
- 生成图：只做 editorial；prompt/model/seed/rights；不冒充视频画面。
- 读者标签：真实帧“视频画面”；派生“根据视频内容绘制”；本文自己的分析“本文的示意整理”；生成“AI 生成示意图”。
- 不要做 section-summary diagram：图必须加信息，不是把上一段再画一遍。
- 图不要和正文打架：节点/边/caption 不能出现正文已经说“未确认/没有”的东西；图表 spec 和正文要一致。

## 4. 写作配合

- 不要用长段文字描述一张图能展示的结构；写“图说明了什么/读者看哪里”。
- 图可以承担结构、节点、数字等“可看图直接获得”的信息；prose 只解释“为什么这图重要/边界在哪”，不要复述图里的每个节点和数值。
- 本节有真正适合图/表的结构时，正文更短：问题、关键例子、takeaway 即可，细节交给图；不要图表和正文各列一遍。
- 图不要抢标题/小节；图放在相关段落之后。
- 一篇文章只放必要的图/表；不为“有图”硬凑。

## 5. 自检

1. 有哪些段落其实应该是图/表？
2. 每张图/表是否直接服务于本节 core point？
3. 真实帧是否真的展示该操作/结果且可读？
4. 图表数据/节点/边是否都能回指证据？
5. caption 是否只写“看哪里”，不是正文摘要？
6. 图/表是否和正文、source line 一致？
7. 生成图/本文示意是否标 editorial，没冒充视频证据？
