# Structure reference：TOC + teaching flow

> 这是 skill 的结构参考，不是模板；按视频内容调整，不按固定 section 数硬套。

## 1. 标题

- 标题要具体：读者看完标题知道文章讲什么对象/问题。
- 一句话，尽量短；不要用堆叠从句或需要副标题才能解释的标题。
- 不要夸张、不要口号；标题可以是问题、对象+动作、或一个有张力的判断。
- 如果有副标题，副标题写“转变/对比/问题”（如“从 A 到 B：……如何……”），不要写一串抽象名词或清单。
- 标题尽量带一个证据里的具体对象/画面/说法，但不要依赖只有看过视频才懂的梗。
- 标题不要依赖“视频里最有趣的一句梗”而牺牲可理解性。
- 标题 + 第一段：第一段必须兑现标题承诺，不要先写背景。

## 2. H2 = 目录

- 4–7 个 H2；每个 H2 具体、平行、能单独说明本节讲什么。
- 只读标题 + H2，读者应能理解文章的框架和推进顺序。
- 每个 H2 尽量短（一个短句/一个对象+动作），不要在标题里塞完整论证。
- 禁止空泛标题：“背景 / 介绍 / 概述 / 总结 / 其他 / 补充”。
- H2 的顺序应该是一条链（问题 → 机制 → 例子/演示 → 张力/边界 → 综合），不是话题清单。
- H3 只在真的有子阶段时用；不要为了排版加标题。

## 3. 每节的 job / takeaway

每节先明确（写作时内部决定，不必输出）：

- **Promise**：读者读完这节能理解/能做什么？
- **Core point**：这一节只讲一个核心点。
- **Example/demo**：这一节用哪个具体例子、演示、画面、数字或对话支撑？
- **Takeaway**：结尾一句话告诉读者“带走什么”。

## 4. Teaching flow（借 bilibili 的教学结构）

每个主要 section 按以下顺序组织，按需省略：

1. **Opening move**：用一个具体场景、对话、问题或反例开场；不要用定义/否定句/“本节讲……”开场。
2. **Motivation/problem**：为什么需要这一节？它解决什么困惑/失败？
3. **Main idea**：这一节最重要的一句话。
4. **Mechanism**：它怎么运作；术语首次出现先解释。
5. **Example/evidence**：具体演示、案例、数字、画面、对话、公式或代码。
6. **Takeaway**：一句话收束，不重复全文。

不要按视频时间顺序复述；按读者的理解顺序重组。

## 5. 文章级结构

- 开头：建立读者问题 + 文章的控制性判断；不要先自我介绍/预告。
- 中段：一条机制/论证/流程链；每节有例子/演示；关键术语首次解释。
- 结尾：synthesis + 作者实质收尾 + 边界/开放问题；不要逐节 recap。
- 结尾给一个自然出口：原片/搜索词/官方文档/下一步；没有来源就说明“来源未提供”，不要编 URL。

## 6. 自检

1. 只看 title + H2，读者能否理解文章框架？
2. 每个 H2 是否具体、平行、能独立说明本节？
3. 每节是否有 promise、core point、example、takeaway？
4. 章节顺序是否按理解推进，而不是按视频时间？
5. 是否有空泛标题、装饰性标题、过长标题？
6. 第一段是否兑现标题？
