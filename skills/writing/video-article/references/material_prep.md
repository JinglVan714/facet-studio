# 素材层 / 写作层分离规范

这份文件给管线和编辑看，不给 Writer 看。Writer 只读 `SKILL.md`，只拿内容稿。

## 原则

**素材归素材，写作归写作。**

- 素材层负责：转写、分段、选帧、复制图示、去掉时间码/ID/帧号/平台元数据、在文章写成后补一行出处。
- 写作层负责：只读内容稿，把这件事写清楚。Writer 不需要知道内容来自视频、素材包、claim 表或任何管线。
- 文章正文里不出现“内容稿/素材/原文/转写/视频/UP 主”这些词。读者只关心内容本身。

## 内容稿格式

`content_manuscript.py` 输出一个 Markdown 文本：

```text
<第一段正文>

（图示 1：<图示说明>；图：figures/fig-01.jpg）

<第二段正文>

（图示 2：<图示说明>；图：figures/fig-02.jpg ｜ 图示 3：...）
```

要求：

- 完整转写，按段落连续排；不抽样、不硬截断。
- 没有标题、UP 主、时长、链接、上传日期、视频 ID、时间码、帧 ID、claim ID。
- 图示说明只放画面文字/OCR；不生成画面描述。没有文字的图示写“无文字”。
- 图示复制到 `figures/fig-01.jpg`、`fig-02.jpg`……并在内容稿里用相对路径引用。
- 每段最多 1–2 个图示；优先长 caption、含数字/表格/代码、场景帧。字幕碎片不堆。
- 不写出处。出处由 `run.py` 在文章写成后按 `source.json` 补一行。

## 写作层边界

- Writer 的 system prompt = `SKILL.md` + `references/examples.md`。
- Writer 的 user prompt = 写作请求 + 内容稿；不提“素材包/视频/转写”。
- Writer 只输出文章正文；不写 brief、自审、JSON、出处。
- 写完后 `run.py` 补出处；`article_checks.py` 检查正文泄漏、时间码、图示路径、标题/出处。
- 素材层的改动（选帧、分段、出处）不能反向要求 Writer 加字段或加 stage。
